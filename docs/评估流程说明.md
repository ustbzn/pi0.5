# DrivePi0 评估流程说明

## 概述

评估流程用于在验证集上测试训练好的模型性能，计算动作准确率、L1损失和L2损失等指标。

## 评估流程

### 1. 启动评估脚本

评估通过运行 `script/evaluation/eval_drivepi0.sh` 脚本启动：

```bash
bash script/evaluation/eval_drivepi0.sh
```

或者在SLURM集群上提交作业：
```bash
sbatch script/evaluation/eval_drivepi0.sh
```

### 2. 脚本执行流程

#### 2.1 脚本入口 (`eval_drivepi0.sh`)
- 配置SLURM作业参数（GPU、内存、时间等）
- 调用 `script/run.py`，指定评估配置文件路径

#### 2.2 主运行脚本 (`script/run.py`)
主要步骤：
1. **加载Hydra配置**：从 `config/eval/DrivePi0/base.yaml` 加载配置
2. **解析配置**：解析所有配置变量（包括 `${now:}` 时间戳等）
3. **初始化分布式训练环境**（如果需要多GPU）
4. **实例化评估代理**：根据配置中的 `_target_` 字段创建 `DrivePiZeroEvalAgent` 实例
5. **运行评估**：调用 `agent.run()` 方法

#### 2.3 评估代理初始化 (`src/agent/drivepi0/eval.py`)

`DrivePiZeroEvalAgent.__init__()` 执行以下初始化：

**模型加载：**
- 创建 `DrivePiZeroInference` 模型实例
- 从 `checkpoint_path` 加载训练好的模型权重
- 冻结所有模型参数（`freeze_all_weights()`）
- 将模型转换为评估模式（`.eval()`）
- 可选：使用 `torch.compile()` 加速推理

**数据加载：**
- 创建 `Bench2DriveDataset` 数据集（使用验证集 split）
- 创建 `DataLoader` 用于批量加载数据
- 设置 batch size、num_workers 等参数

**处理器初始化：**
- 加载 tokenizer（从预训练模型路径）
- 创建 `VLAProcessor` 用于处理多模态输入（图像+文本）

### 3. 评估执行过程

`DrivePiZeroEvalAgent.run()` 方法执行实际评估：

#### 3.1 数据批处理循环

对验证集的每个batch：

1. **数据预处理** (`preprocess_batch` 函数)：
   - 提取图像（前视、前视历史、后视）
   - 提取状态信息（proprioceptive state）
   - 提取轨迹标签（ground truth actions）
   - 提取语言指令文本
   - 使用 `VLAProcessor` 处理图像和文本，生成模型输入：
     - `input_ids`：文本token ids
     - `pixel_values`：图像像素值
     - `attention_mask`：注意力掩码
   - 构建因果掩码和位置编码（`build_causal_mask_and_position_ids`）

2. **模型推理**：
   - 调用 `model.infer_action()` 进行动作预测
   - 推理过程包括：
     - **视觉编码**：使用SigLIP编码图像
     - **文本编码**：使用tokenizer编码语言指令
     - **状态编码**：编码proprioceptive状态
     - **联合模型前向传播**：通过VLM和proprio分支，缓存KV
     - **Flow Matching采样**：
       - 从随机噪声开始
       - 通过多次迭代（`num_inference_steps`）逐步去噪
       - 使用Euler积分方法
     - **动作解码**：输出最终的动作轨迹

3. **指标计算**：
   - **动作准确率**：使用 `get_action_accuracy()` 计算
     - 在多个阈值（0.05, 0.1, 0.2, 0.3, 0.5）下计算准确率
     - 判断预测动作与真实动作的差异是否小于阈值
   - **L1损失**：平均绝对误差
   - **L2损失**：均方误差
   - 注意：计算损失前会将轨迹反归一化到原始坐标空间

4. **累积统计**：
   - 累计所有batch的准确率、L1损失、L2损失

#### 3.2 结果汇总

评估完成后：
- 计算平均准确率（各阈值）
- 计算平均L1损失
- 计算平均L2损失
- 记录日志输出

## 配置要点

在 `config/eval/DrivePi0/base.yaml` 中需要配置：

1. **模型路径**：
   ```yaml
   pretrained_model_path: "YOUR_MODEL_PATH"  # 预训练模型路径
   checkpoint_path: "YOUR_CHECKPOINT_PATH"  # 训练好的checkpoint路径
   ```

2. **数据路径**：
   ```yaml
   current_dir: "YOUR_CURRENT_WORK_DIR"  # 工作目录
   data:
     work_dir: ${current_dir}
     statistics_path: ${current_dir}/statistics.json
     split: val  # 使用验证集
   ```

3. **评估参数**：
   ```yaml
   device_batch_size: 32  # 批次大小
   eval_thresholds: [0.05, 0.1, 0.2, 0.3, 0.5]  # 准确率阈值
   num_inference_steps: 10  # Flow Matching采样步数
   ```

## 评估输出

评估会在日志中输出：
- 评估的episode数量
- L1损失值
- L2损失值
- 各个阈值下的动作准确率

示例输出：
```
Eval | l1 Loss: 0.123 | l2 Loss: 0.045 | acc thres 0.05: 0.856 | acc thres 0.1: 0.923 | ...
```

## Flow Matching推理过程详解

模型使用Flow Matching进行动作生成：

1. **初始化**：从标准高斯分布采样随机噪声作为初始动作
2. **迭代去噪**：进行 `num_inference_steps` 次迭代
   - 将当前动作和时间步编码为embedding
   - 通过联合模型预测动作的"速度"（action velocity）
   - 使用Euler方法更新动作：`action += delta_t * action_vel`
   - 时间步递增：`t += delta_t`
3. **裁剪输出**：将最终动作裁剪到 `[-final_action_clip_value, final_action_clip_value]` 范围内

## 注意事项

1. **模型状态**：评估前会自动将模型设为 `.eval()` 模式
2. **GPU内存**：确保有足够的GPU内存（脚本默认配置40G）
3. **数据路径**：确保所有数据路径配置正确
4. **归一化**：损失计算使用反归一化后的轨迹，确保使用正确的统计文件
5. **分布式评估**：当前脚本配置为单GPU评估，如需多GPU需修改配置
