# Drive_pi 工程技术梳理

> 版本基线：基于当前仓库代码结构扫描（`Drive_pi/`）  
> 目标：给出可执行的工程地图，明确“数据 -> 训练 -> 推理 -> 评估”的主链路，并标注当前技术债

---

## 1. 工程定位

`Drive_pi` 是一个以 `DrivePi0` 为核心的端到端轨迹预测/驾驶决策工程，当前同时支持：

- `MOGO` 数据链路（rosbag -> json/pkl -> 训练/推理）
- `nuScenes` 数据链路（json/pkl -> 训练/推理）
- `Bench2Drive` 链路（原始 route 数据 -> pkl -> 训练/评估）

当前主代码已明显向 `Qwen3-VL` 迁移，但仓库中仍保留 `PaliGemma` 时代的配置与脚本。

---

## 2. 目录与职责总览

按文件数量统计，`Drive_pi` 约 348 个文件，其中：

- `mogo-dataset-tools`：236（含大量 protobuf 生成文件）
- `src`：54（核心训练/推理/模型代码）
- `config`：16（Hydra 配置）
- `script`：13（启动与预处理脚本）
- `docs`：13（文档）

核心目录职责如下：

| 目录 | 职责 |
|---|---|
| `src/agent/drivepi0` | 训练、推理、评估入口实现（Agent 层） |
| `src/model/DrivePi0` | `DrivePiZero` 主模型、联合注意力（mixture）与处理器 |
| `src/data` | `Dataset` 定义与归一化、图像读取 |
| `src/data_processing` | Bench2Drive/通用 pkl 预处理、窗口切片、统计量生成 |
| `config/train|eval|inference` | Hydra 配置族（多套实验模板） |
| `script/training|evaluation|data_preprocessing` | 实际运行脚本（SLURM/本地） |
| `mogo-dataset-tools` | MOGO 数据集构建工具链（rosbag/json/pkl/划分） |
| `nuscene-dataset-tools` | nuScenes 数据转换与拆分脚本 |
| `src/agent/team_code` | 闭环评测（Bench2Drive CARLA agent） |

## 3. 主执行链路（运行入口）

### 3.1 训练主链路

训练入口统一经：

```text
script/training/*.sh
  -> torchrun script/run.py
    -> Hydra 加载 config/train/DrivePi0/*.yaml
      -> src.agent.drivepi0.train.DrivePiZeroTrainAgent
        -> model + dataloader + optimizer + train loop
```

关键文件：

- `script/run.py`
- `script/training/train_drivepi0.sh`（默认 `base_nuscene.yaml`）
- `script/training/train_drivepi0_mogo.sh`（当前默认 `qwen3.yaml`）
- `src/agent/drivepi0/train.py`

### 3.2 推理主链路

推理脚本多数是 `argparse + OmegaConf.load` 直启，不走 Hydra `_target_`：

- `src/agent/drivepi0/inference_mogo_test.py`（Qwen3 路线）
- `src/agent/drivepi0/inference_nuscene_test.py`（Qwen3 路线）
- `src/agent/drivepi0/inference_mogo.py`、`inference_nuscene.py`（历史/兼容）

`script/inference.sh` 当前对接 `inference_mogo_test.py`。

### 3.3 评估主链路

评估通过 Hydra：

```text
script/evaluation/eval_drivepi0.sh
  -> torchrun script/run.py --config-path ../config/eval/DrivePi0
    -> src.agent.drivepi0.eval.DrivePiZeroEvalAgent
```

## 4. 数据工程链路梳理

## 4.1 MOGO：rosbag 到训练样本

主要链路分两代实现：

- 老链路：`parseRosBag-2O_py27.py`（Python2.7）
- 新链路：`parseRosBag-2O_py3.py` / `parseRosBag-2O-Poutine_jun.py`（Python3）

当前脚本化入口：

- `mogo-dataset-tools/1_general_json.sh`：rosbag + image -> json
- `mogo-dataset-tools/2_general_pkl.sh`：json -> pkl

常见后处理：

- `json_to_pkl*.py`
- `move_pkl_files*.py`
- `get_statistics_mogo.py` / `get_statistics_mogo_all.py`

## 4.2 Bench2Drive：route 级原始数据到样本

链路：

```text
script/data_preprocessing/generate_data.sh
  -> src/data_processing/generate_data.py
    输出 train_data.pkl / val.pkl

script/data_preprocessing/window.sh
  -> src/data_processing/window.py
    输出逐样本 pkl（dynamic/val + 可选 fixed/train）

script/data_preprocessing/get_statistics.sh
  -> src/data_processing/get_statistics.py
```

`window.py` 会按 `window_size`、`horizon`、`stride` 切窗，并将世界坐标转 ego 坐标。

## 4.3 nuScenes：json 到 pkl

链路：

- `nuscene-dataset-tools/drivepi_nusc_data_converter.py`（原始转换）
- `collect_split_json.py`（按 `_train/_val` 后缀拆分）
- `json_to_pkl_converter.py`（字段映射并写 pkl）

## 5. 模型与训练机制

## 5.1 主模型结构

主类：`src/model/DrivePi0/drivepi0.py::DrivePiZero`

主要模块：

- 文本嵌入：`embed_tokens`
- 视觉塔：Qwen3-VL vision（从 HF 模型拆出）
- 联合模型：`JointModel`（mixture 机制）
- 编码器：`proprio_encoder`、`action_encoder`、`time_embedding`
- 解码器：`action_decoder`

## 5.2 JointModel（跨 mixture 注意力）

关键文件：`src/model/DrivePi0/joint_model.py`

要点：

- `vlm/proprio/action` 三个 mixture 联合 attention
- `action/proprio` 按 `vlm` 层数 2:1 下采样更新（`action_layer_idx = vlm_layer_idx // 2`）
- 支持 KV cache，多模式：`append` / `no_append` / `append_non_active`

## 5.3 训练目标与推理方式

- 训练：Flow Matching（`psi_t` 插值 + 速度场回归 MSE）
- 推理：从高斯噪声动作起步，Euler 迭代 `num_inference_steps` 次

## 5.4 输入特征与归一化

`src/data/dataset.py` 读取每条 pkl，输出：

- `state`（速度/加速度/角速度/theta/导航点）
- `trajectory`（`fur_x/fur_y`）
- 图像（主要使用 `front + front_time`）
- 文本指令（默认 `"predict trajectory"`）

归一化由 `src/data/utils/normalization.py::Normalize` 统一处理，支持：

- `percentile`
- `percentile_clip`
- `minmax`

## 7. 当前技术债与风险点

以下为“影响可维护性/可复现实验”的关键项：

1. 安全与环境耦合  
`script/training/*.sh`、`script/evaluation/*.sh` 存在明文 `SWANLAB_API_KEY`、大量绝对路径。

2. 配置与代码存在代际混合  
主训练 `train.py` 已偏 Qwen3-VL，但仍保留 PaliGemma 配置族与历史脚本，易产生误配。

3. 训练数据加载未做 DDP 分片  
`train.py` 的 `DataLoader` 未配 `DistributedSampler`，多卡下样本重复风险高。

4. 代码重复入口较多  
`inference*.py` / `*_test.py` / `*_old.py`、`train_val_dataiterator.py` 并存，维护成本高。

5. `Normalize` 为进程级单例  
同进程切换不同 `statistics_path` 时可能复用旧实例，存在隐性错误风险。

6. 部分工具函数存在“疑似废弃”代码  
如 `src/data/utils/image.py` 中 `concatenate_images` 使用未定义变量，当前看未被主链路使用。

---

## 8. 建议的收敛路线（可直接排期）

1. 统一入口与配置命名  
明确 `qwen3` 为主分支，`paligemma` 作为 legacy 子目录或独立分支。

2. 收敛推理脚本  
保留一个 MOGO/nuScenes 推理入口，参数化 `dataset_type`，移除 `*_old/*_test` 重复逻辑。

3. 修正多卡数据并行  
训练 DataLoader 增加 `DistributedSampler`，并显式设置 `shuffle`。

4. 清理环境硬编码  
移除 key 明文与绝对路径，统一改为环境变量 + 默认值。

5. 规范数据工具边界  
`mogo-dataset-tools` 中 py2/py3 脚本分层，标注“推荐入口”并冻结历史版本。
