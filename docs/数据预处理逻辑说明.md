# 数据预处理逻辑说明

## 一、整体流程

数据预处理分为两个阶段，由两个脚本完成：

### 阶段1：`generate_data.py` - 原始数据组织
### 阶段2：`window.py` - 窗口切片与样本生成

---

## 二、阶段1：generate_data.py 详细逻辑

### 2.1 功能概述
将原始 Bench2Drive 数据组织成 episode 列表，并划分为训练集和验证集。

### 2.2 输入数据
- **原始数据路径**：包含多个 route 目录，每个 route 目录下包含：
  - `anno/`: 标注文件（`.json.gz`）
  - `camera/`: 六路相机图片（`rgb_front`, `rgb_front_left`, `rgb_front_right`, `rgb_back`, `rgb_back_left`, `rgb_back_right`）
  - `expert_assessment/`: 专家动作评估（`.npz`）
- **相机标签路径**：包含每个 route 的相机 ID 标签文件（`<RouteName>.json`）

### 2.3 处理流程

#### 步骤1：读取单条 route 数据 (`get_data_info`)
1. **统计帧数**：通过 `anno/` 目录下的 `.json.gz` 文件数量确定 `step_sum`
2. **读取标注**：逐帧读取标注文件，提取位置、速度、角度、命令等信息
3. **构建相机路径**：为每帧构建六路相机的图片路径列表
4. **读取专家评估**：读取每帧的专家动作（注意：专家评估文件从 `-1` 开始编号）
5. **读取相机标签**：从 `<RouteName>.json` 读取每帧的 `cam_id`
6. **数据对齐**：
   - 观测序列：去掉最后一帧（因为观测比动作多1帧）
   - 动作序列：去掉首帧（首帧无前一动作）
   - 最终对齐：`obs_t + act_t -> obs_{t+1}`

#### 步骤2：划分训练/验证集 (`deal_with_data`)
- 根据硬编码的 `val_list` 将 route 分为：
  - **训练集**：不在 `val_list` 中的 route
  - **验证集**：在 `val_list` 中的 route

#### 步骤3：保存数据
- **训练集**：保存到 `b2d_dynamic_camera/train/train_data.pkl`
- **验证集**：保存到 `b2d_dynamic_camera/val/val.pkl`

每个 pkl 文件包含一个列表，列表中每个元素是一个 episode（元组），包含：
- 位置、速度、角度等状态序列
- 六路相机图片路径序列
- 动作序列
- 相机 ID 序列
- 场景元信息（scenario_id, town_id, route_id, weather_id）

### 2.4 输出文件结构
```
work_dir/
└── b2d_dynamic_camera/
    ├── train/
    │   └── train_data.pkl  # 训练集 episode 列表
    └── val/
        └── val.pkl  # 验证集 episode 列表
```

## 三、阶段2：window.py 详细逻辑

### 3.1 功能概述
对每个 episode 进行窗口切片，生成单个样本的 pkl 文件。

### 3.2 核心参数
- **window_size**：历史窗口大小（例如 5）
- **horizon**：未来轨迹长度（例如 10）
- **stride**：下采样步长（例如 stride=5 将 10Hz 数据降为 2Hz）

### 3.3 处理流程

#### 步骤1：加载 episode 数据
- 从 `train_data.pkl` 或 `val.pkl` 加载所有 episode
- 删除原始 pkl 文件（第33行）

#### 步骤2：下采样（可选）
如果 `stride > 1`，对所有序列进行等间隔采样：
```python
episode_x_list = episode_x_list[::s]  # 例如 stride=5: [0, 5, 10, 15, ...]
```

#### 步骤3：窗口切片 (`_split_data`)

##### 3.3.1 历史状态窗口 (`state_window`)
```python
def state_window(traj: list, window_size: int):
    traj_len = len(traj)
    # 为每个时间步生成历史窗口索引
    history_indices = tf.range(traj_len)[:, None] + tf.range(-window_size + 1, 1)
    # 边界处理：负数索引设为 0（用第一帧填充）
    history_indices = tf.maximum(history_indices, 0)
    result = tf.gather(traj, history_indices)  # [traj_len, window_size, state_dim]
    return result
```

**示例**（window_size=5）：
- 时间步 0: 索引 [-4, -3, -2, -1, 0] → 填充为 [0, 0, 0, 0, 0]（用第一帧填充）
- 时间步 1: 索引 [-3, -2, -1, 0, 1] → 填充为 [0, 0, 0, 0, 1]
- 时间步 4: 索引 [0, 1, 2, 3, 4] → 正常窗口
- 时间步 N: 索引 [N-4, N-3, N-2, N-1, N] → 正常窗口

##### 3.3.2 未来轨迹窗口 (`trajectory_window`)
```python
def trajectory_window(traj: list, window_size: int, horizon: int):
    traj_len = len(traj)
    true_len = traj_len - horizon + 1  # 有效样本数
    
    # 历史窗口索引（与 state_window 相同）
    history_indices = tf.range(traj_len)[:, None] + tf.range(-window_size + 1, 1)
    history_indices = tf.maximum(history_indices, 0)
    
    # 未来轨迹索引
    action_chunk_indices = tf.range(traj_len)[:, None] + tf.range(horizon)
    # 边界处理：超出范围的索引设为最后一帧（用最后一帧填充）
    action_chunk_indices = tf.minimum(action_chunk_indices, traj_len - 1)
    
    traj = tf.gather(traj, action_chunk_indices)  # [traj_len, horizon, action_dim]
    traj = tf.gather(traj, history_indices)  # [traj_len, window_size, horizon, action_dim]
    
    # 截断：只保留有效样本（保证未来轨迹完整）
    traj = traj[:true_len]
    return traj
```

**示例**（horizon=10, window_size=1）：
- 时间步 0: 未来索引 [0, 1, 2, ..., 9] → 正常
- 时间步 N-9: 未来索引 [N-9, N-8, ..., N] → 正常
- 时间步 N-8: 未来索引 [N-8, N-7, ..., N, N] → 最后一个索引被填充为 N
- 时间步 N: 未来索引 [N, N, N, ..., N] → 全部填充为最后一帧
- **最终输出**：只保留前 `traj_len - horizon + 1` 个样本

#### 步骤4：构建样本字典
对每个有效样本（索引 `i`），构建包含以下字段的字典：
- `his_*`: 历史窗口数据（长度为 window_size）
- `fur_x`, `fur_y`: 未来轨迹（长度为 horizon）
- `step`: 样本编号
- 场景元信息

#### 步骤5：坐标转换与数据保存 (`_process_data`)
1. **坐标转换**：将世界坐标转换为自车坐标系
   - `his_theta`: 相对角度（减去当前角度）
   - `x_command_*`, `y_command_*`: 命令点坐标转换
   - `fur_x`, `fur_y`: 未来轨迹坐标转换
2. **动作编码**：将动作转换为 one-hot 编码（39 维）
3. **保存样本**：
   - **动态相机数据**：保存到 `b2d_dynamic_camera/train/` 或 `b2d_dynamic_camera/val/`
   - **固定相机数据**（可选，仅训练集）：保存到 `b2d_fixed_camera/`

### 3.4 输出文件结构
```
work_dir/
├── b2d_dynamic_camera/
│   ├── train/
│   │   ├── <scenario>_<town>_<route>_<weather>_step0.pkl
│   │   ├── <scenario>_<town>_<route>_<weather>_step1.pkl
│   │   └── ...
│   └── val/
│       ├── <scenario>_<town>_<route>_<weather>_step0.pkl
│       └── ...
└── b2d_fixed_camera/  # 可选，仅训练集
    ├── <scenario>_<town>_<route>_<weather>_step0_frontleft.pkl
    ├── <scenario>_<town>_<route>_<weather>_step0_frontright.pkl
    └── ...
```

## 四、边界情况处理分析

### 4.1 历史帧不足的情况

**问题**：当 episode 长度 < window_size 时，无法提供完整的历史窗口。

**处理方式**：
- 在 `state_window` 函数中，使用 `tf.maximum(history_indices, 0)` 将负数索引设为 0
- **效果**：用第一帧重复填充，保证窗口大小始终为 `window_size`

**示例**：
- episode 长度 = 3，window_size = 5
- 时间步 0: 历史窗口 = [帧0, 帧0, 帧0, 帧0, 帧0]
- 时间步 1: 历史窗口 = [帧0, 帧0, 帧0, 帧0, 帧1]
- 时间步 2: 历史窗口 = [帧0, 帧0, 帧0, 帧1, 帧2]

**影响**：
- ✅ 不会报错，可以正常处理
- ⚠️ 前几帧的历史信息可能不够丰富（用第一帧填充）

### 4.2 未来帧不足的情况

**问题**：当 episode 长度 < horizon 时，无法提供完整的未来轨迹。

**处理方式**：
1. 在 `trajectory_window` 函数中，使用 `tf.minimum(action_chunk_indices, traj_len - 1)` 将超出范围的索引设为最后一帧
2. **关键**：通过 `traj = traj[:true_len]` 截断，只保留有效样本
   - `true_len = traj_len - horizon + 1`
   - 如果 `traj_len < horizon`，则 `true_len <= 0`，不会生成任何样本

**示例1**：正常情况（traj_len=100, horizon=10）
- `true_len = 100 - 10 + 1 = 91`
- 生成 91 个样本（索引 0-90）
- 最后一个样本（索引 90）的未来轨迹：索引 [90, 91, ..., 99]

**示例2**：边界情况（traj_len=5, horizon=10）
- `true_len = 5 - 10 + 1 = -4`
- 由于 `true_len <= 0`，`traj[:true_len]` 返回空列表
- **结果**：该 episode 不会生成任何样本

**示例3**：临界情况（traj_len=10, horizon=10）
- `true_len = 10 - 10 + 1 = 1`
- 只生成 1 个样本（索引 0）
- 该样本的未来轨迹：索引 [0, 1, 2, ..., 9]（正好完整）

### 4.3 总结

| 情况 | 历史帧处理 | 未来帧处理 | 结果 |
|------|-----------|-----------|------|
| `traj_len >= window_size` 且 `traj_len >= horizon` | ✅ 正常窗口 | ✅ 正常轨迹 | ✅ 生成 `traj_len - horizon + 1` 个样本 |
| `traj_len < window_size` 且 `traj_len >= horizon` | ⚠️ 用第一帧填充 | ✅ 正常轨迹 | ✅ 生成 `traj_len - horizon + 1` 个样本（前几个样本历史信息不足） |
| `traj_len >= window_size` 且 `traj_len < horizon` | ✅ 正常窗口 | ❌ 无法提供完整轨迹 | ❌ 不生成样本（`true_len <= 0`） |
| `traj_len < window_size` 且 `traj_len < horizon` | ⚠️ 用第一帧填充 | ❌ 无法提供完整轨迹 | ❌ 不生成样本（`true_len <= 0`） |

### 4.4 建议

1. **数据过滤**：在 `generate_data.py` 阶段，可以过滤掉长度过短的 episode（例如 `traj_len < horizon`）
2. **参数设置**：确保 `horizon` 不要设置过大，避免大量 episode 被过滤
3. **监控**：在 `window.py` 中添加日志，记录被跳过的 episode 数量

## 五、数据流示例

### 示例：一个完整的处理流程

**原始数据**：
```
Bench2Drive-Base/
└── Accident_Town03_Route101_Weather23/
    ├── anno/
    │   ├── 00000.json.gz
    │   ├── 00001.json.gz
    │   └── ... (共 200 帧)
    ├── camera/
    │   ├── rgb_front/
    │   └── ...
    └── expert_assessment/
```

**阶段1输出** (`train_data.pkl`)：
```python
[
    (episode_x_list, episode_y_list, ..., scenario_id, town_id, route_id, weather_id),
    # ... 更多 episode
]
```

**阶段2输出** (假设 window_size=5, horizon=10, stride=1)：
- 如果 episode 长度为 200，下采样后仍为 200
- 生成 `200 - 10 + 1 = 191` 个样本
- 每个样本包含：
  - 历史窗口：5 帧
  - 未来轨迹：10 帧
  - 当前状态：1 帧

**文件命名**：
- `Accident_Town03_Route101_Weather23_step0.pkl`
- `Accident_Town03_Route101_Weather23_step1.pkl`
- ...
- `Accident_Town03_Route101_Weather23_step190.pkl`
