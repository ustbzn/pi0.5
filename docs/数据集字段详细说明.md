# 数据集字段详细说明文档

## 概述

本文档详细说明 Bench2Drive 数据集预处理后生成的 pkl 文件中每个字段的含义、数据类型、形状和用途。

## 文件类型

数据集包含两种类型的样本文件：

1. **动态相机样本** (`b2d_dynamic_camera/`)
   - 包含所有 6 路相机路径
   - 包含 `cam_id` 字段（可能为 `NULL` 或特定视角标识）
   - 用于动态视角训练（`use_fixed_images=False`）

2. **固定相机样本** (`b2d_fixed_camera/`)
   - 包含前视相机 + 一个固定的 `skill_cam` 视角
   - 文件名后缀标识固定视角（`_frontleft`, `_frontright`, `_back`, `_backleft`, `_backright`）
   - 用于固定视角训练（`use_fixed_images=True`）

## 字段分类

### 1. 历史状态数据 (History State Data)

这些字段包含过去 `window_size=5` 个时间步的状态信息。

#### 1.1 `his_theta`
- **类型**: `numpy.ndarray`
- **形状**: `(5,)`
- **数据类型**: `float32`
- **单位**: 弧度 (rad)
- **说明**: 历史航向角序列，相对于当前帧的航向角变化。当前帧作为参考坐标系原点，因此最后一个值通常为 0。
- **示例**: `[0., 0., 0., 0., 0.]`
- **用途**: 提供车辆历史朝向信息，用于预测未来轨迹

#### 1.2 `his_speed`
- **类型**: `numpy.ndarray`
- **形状**: `(5,)`
- **数据类型**: `float32`
- **单位**: 米/秒 (m/s)
- **说明**: 历史速度序列，包含过去 5 个时间步的车辆速度。
- **示例**: `[9.074877e-07, 9.074877e-07, 9.074877e-07, 9.074877e-07, 9.074877e-07]`
- **用途**: 提供车辆历史运动速度信息

#### 1.3 `his_acceleration`
- **类型**: `numpy.ndarray`
- **形状**: `(5, 3)`
- **数据类型**: `float32`
- **单位**: 米/秒² (m/s²)
- **说明**: 历史加速度序列，每个时间步包含 3 个分量：
  - `[0]`: x 方向加速度（纵向）
  - `[1]`: y 方向加速度（横向）
  - `[2]`: z 方向加速度（垂直）
- **示例**: `[[1.3986786e-04, 6.5990811e-04, 9.7717285e+00], ...]`
- **用途**: 提供车辆历史加速度信息，用于理解车辆运动状态变化

#### 1.4 `his_angular_velocity`
- **类型**: `numpy.ndarray`
- **形状**: `(5, 3)`
- **数据类型**: `float32`
- **单位**: 弧度/秒 (rad/s)
- **说明**: 历史角速度序列，每个时间步包含 3 个分量：
  - `[0]`: roll（横滚角速度）
  - `[1]`: pitch（俯仰角速度）
  - `[2]`: yaw（偏航角速度）
- **示例**: `[[0.00094643, -0.00060577, -0.0008266], ...]`
- **用途**: 提供车辆历史旋转角速度信息

#### 1.5 `his_action`
- **类型**: `numpy.ndarray`
- **形状**: `(5, 39)`
- **数据类型**: `uint8`
- **说明**: 历史动作序列，采用 one-hot 编码。每个时间步的动作是一个 39 维向量，其中只有一个位置为 1，其余为 0。
- **示例**: `[[0, 0, ..., 1, 0, ...], ...]` (第 25 个位置为 1)
- **用途**: 提供历史动作信息，39 个动作类别可能包括不同的速度、转向等离散动作

### 2. 导航指令数据 (Navigation Command Data)

这些字段包含导航系统的指令信息，用于指导车辆行驶。

#### 2.1 `x_command_far`
- **类型**: `numpy.ndarray`
- **形状**: `(5,)`
- **数据类型**: `float32`
- **单位**: 米 (m)
- **坐标系**: 自车坐标系
- **说明**: 远距离导航点的 x 坐标序列。在自车坐标系中，x 轴通常指向前方。
- **示例**: `[51.214245, 51.214245, 51.214245, 51.214245, 51.214245]`
- **用途**: 提供远距离导航目标点位置

#### 2.2 `y_command_far`
- **类型**: `numpy.ndarray`
- **形状**: `(5,)`
- **数据类型**: `float32`
- **单位**: 米 (m)
- **坐标系**: 自车坐标系
- **说明**: 远距离导航点的 y 坐标序列。在自车坐标系中，y 轴通常指向左侧。
- **示例**: `[-1.5509049, -1.5509049, -1.5509049, -1.5509049, -1.5509049]`
- **用途**: 提供远距离导航目标点位置

#### 2.3 `x_command_near`
- **类型**: `numpy.ndarray`
- **形状**: `(5,)`
- **数据类型**: `float32`
- **单位**: 米 (m)
- **坐标系**: 自车坐标系
- **说明**: 近距离导航点的 x 坐标序列。
- **示例**: `[4.000028, 4.000028, 4.000028, 4.000028, 4.000028]`
- **用途**: 提供近距离导航目标点位置

#### 2.4 `y_command_near`
- **类型**: `numpy.ndarray`
- **形状**: `(5,)`
- **数据类型**: `float32`
- **单位**: 米 (m)
- **坐标系**: 自车坐标系
- **说明**: 近距离导航点的 y 坐标序列。
- **示例**: `[7.909909e-05, 7.909909e-05, 7.909909e-05, 7.909909e-05, 7.909909e-05]`
- **用途**: 提供近距离导航目标点位置

#### 2.5 `command_near`
- **类型**: `numpy.ndarray`
- **形状**: `(5,)`
- **数据类型**: `float32`
- **说明**: 近距离导航指令的离散类别值。可能表示不同的导航指令类型（如直行、左转、右转等）。
- **示例**: `[4., 4., 4., 4., 4.]`
- **用途**: 提供近距离导航指令类别

#### 2.6 `command_far`
- **类型**: `numpy.ndarray`
- **形状**: `(5,)`
- **数据类型**: `float32`
- **说明**: 远距离导航指令的离散类别值。
- **示例**: `[4., 4., 4., 4., 4.]`
- **用途**: 提供远距离导航指令类别

### 3. 未来轨迹数据 (Future Trajectory Data)

这些字段包含未来 `horizon=10` 步的轨迹预测目标。

#### 3.1 `fur_x`
- **类型**: `numpy.ndarray`
- **形状**: `(1, 10)`
- **数据类型**: `float32`
- **单位**: 米 (m)
- **坐标系**: 自车坐标系
- **说明**: 未来轨迹的 x 坐标序列。包含未来 10 个时间步的 x 坐标预测值。
- **示例**: `[[0.0000000e+00, 0.0000000e+00, 0.0000000e+00, 0.0000000e+00, 1.5258596e-05, 5.0415553e-02, 1.6054723e-01, 3.1679162e-01, 5.2258998e-01, 7.8145921e-01]]`
- **用途**: 作为训练目标，模型需要预测未来轨迹的 x 坐标

#### 3.2 `fur_y`
- **类型**: `numpy.ndarray`
- **形状**: `(1, 10)`
- **数据类型**: `float32`
- **单位**: 米 (m)
- **坐标系**: 自车坐标系
- **说明**: 未来轨迹的 y 坐标序列。包含未来 10 个时间步的 y 坐标预测值。
- **示例**: `[[0.0000000e+00, 0.0000000e+00, 0.0000000e+00, 0.0000000e+00, -7.6648256e-08, -2.4366906e-05, -2.8266222e-05, -1.9659055e-05, 7.5721880e-05, 2.0969240e-04]]`
- **用途**: 作为训练目标，模型需要预测未来轨迹的 y 坐标

### 4. 相机数据 (Camera Data)

这些字段包含相机图像的路径信息。

#### 4.1 `his_cam_front`
- **类型**: `tf.Tensor` (string)
- **形状**: `()`
- **说明**: 前视相机图像的完整路径（当前帧）。
- **示例**: `b'/D2/NXT/vlm/miaobinqi/DriveMoE/Bench2Drive-Base/StaticCutIn_Town05_Route226_Weather18/camera/rgb_front/00000.jpg'`
- **用途**: 提供前视相机图像路径，用于视觉感知

#### 4.2 `his_cam_front_time`
- **类型**: `tf.Tensor` (string)
- **形状**: `()`
- **说明**: 前视相机图像的完整路径（前一帧）。
- **示例**: `b'/D2/NXT/vlm/miaobinqi/DriveMoE/Bench2Drive-Base/StaticCutIn_Town05_Route226_Weather18/camera/rgb_front/00000.jpg'`
- **用途**: 提供前一帧的前视相机图像路径，用于时序信息

#### 4.3 `his_cam_front_left`
- **类型**: `tf.Tensor` (string)
- **形状**: `()`
- **说明**: 前左相机图像的完整路径。
- **用途**: 提供前左视角图像路径（仅在动态相机样本中存在）

#### 4.4 `his_cam_front_right`
- **类型**: `tf.Tensor` (string)
- **形状**: `()`
- **说明**: 前右相机图像的完整路径。
- **用途**: 提供前右视角图像路径（仅在动态相机样本中存在）

#### 4.5 `his_cam_back`
- **类型**: `tf.Tensor` (string)
- **形状**: `()`
- **说明**: 后视相机图像的完整路径。
- **用途**: 提供后视角图像路径（仅在动态相机样本中存在）

#### 4.6 `his_cam_back_time`
- **类型**: `tf.Tensor` (string)
- **形状**: `()`
- **说明**: 后视相机图像的完整路径（前一帧）。
- **用途**: 提供前一帧的后视相机图像路径（仅在动态相机样本中存在）

#### 4.7 `his_cam_back_left`
- **类型**: `tf.Tensor` (string)
- **形状**: `()`
- **说明**: 后左相机图像的完整路径。
- **用途**: 提供后左视角图像路径（仅在动态相机样本中存在）

#### 4.8 `his_cam_back_right`
- **类型**: `tf.Tensor` (string)
- **形状**: `()`
- **说明**: 后右相机图像的完整路径。
- **用途**: 提供后右视角图像路径（仅在动态相机样本中存在）

#### 4.9 `skill_cam` (仅固定相机样本)
- **类型**: `tf.Tensor` (string)
- **形状**: `()`
- **说明**: 固定视角相机图像的完整路径。根据文件名后缀确定是哪个视角（frontleft, frontright, back, backleft, backright）。
- **示例**: `b'/D2/NXT/vlm/miaobinqi/DriveMoE/Bench2Drive-Base/StaticCutIn_Town05_Route226_Weather18/camera/rgb_back_right/00000.jpg'`
- **用途**: 提供固定视角图像路径，用于固定视角训练

#### 4.10 `cam_id` (仅动态相机样本)
- **类型**: `tf.Tensor` (string)
- **形状**: `()`
- **说明**: 相机标签，指示该时间步推荐使用的相机视角。可能的值：
  - `"NULL"`: 无特定视角推荐
  - `"CAM_FRONT"`: 前视相机
  - `"CAM_FRONT_LEFT"`: 前左相机
  - `"CAM_FRONT_RIGHT"`: 前右相机
  - `"CAM_BACK"`: 后视相机
  - `"CAM_BACK_LEFT"`: 后左相机
  - `"CAM_BACK_RIGHT"`: 后右相机
- **示例**: `b'NULL'`
- **用途**: 提供相机选择标签，用于动态视角训练

### 5. 元数据 (Metadata)

#### 5.1 `status`
- **类型**: `str`
- **说明**: 样本的唯一标识符，格式为：`<scenario>_<town>_<route>_<weather>_step<X>[_视角]`
- **示例**: 
  - 动态相机: `'StaticCutIn_Town05_Route226_Weather18_step0'`
  - 固定相机: `'StaticCutIn_Town05_Route226_Weather18_step0_backright'`
- **用途**: 用于唯一标识每个样本，便于调试和追踪

## 数据预处理说明

### 坐标系转换

所有位置相关的数据（导航点、轨迹）都已从全局坐标系转换到**自车坐标系**：
- **x 轴**: 指向前方（车辆前进方向）
- **y 轴**: 指向左侧
- **原点**: 当前帧的车辆位置

### 时间对齐

数据遵循 `obs_t + act_t -> obs_{t+1}` 的时序关系：
- 观测数据（状态、图像）去掉最后一帧
- 动作数据去掉第一帧
- 确保每个观测都有对应的动作和下一帧观测

### 滑窗处理

- **历史窗口**: `window_size=5`，包含过去 5 个时间步的状态
- **预测窗口**: `horizon=10`，需要预测未来 10 步的轨迹
- 由于需要完整的未来轨迹，最后 `horizon-1=9` 个时间步无法生成样本

### 数据归一化

所有数值数据都经过了归一化处理，具体归一化参数保存在 `statistics.json` 文件中。

import pickle

# 读取动态相机样本

## 注意事项

1. **TensorFlow Tensor**: 相机路径字段是 TensorFlow Tensor 类型，需要使用 `.numpy().decode('utf-8')` 转换为 Python 字符串

2. **坐标系**: 所有位置数据都在自车坐标系中，使用时需要注意坐标系定义

3. **时间步对齐**: 历史窗口和未来轨迹的时间步数不同，使用时需要正确对齐

4. **数据完整性**: 确保所有必需的字段都存在，某些字段可能因场景不同而有所差异

5. **文件路径**: 相机图像路径是绝对路径，确保路径存在且可访问

# 分析 `generate_data.py`，`window.py` 这两个文件分别生成的字段，以及 `camera_labels` 的使用方式：

## 字段生成流程

### 1. `generate_data.py` 生成的字段

该文件生成中间 pkl 文件（`train_data.pkl` / `val.pkl`），每个元素是一个元组，包含：

**位置与姿态数据：**
- `episode_x_list`, `episode_y_list` - 车辆位置（全局坐标系）
- `episode_x_pure_list`, `episode_y_pure_list` - 车辆纯位置（从 bounding_boxes 提取）
- `episode_theta_list` - 航向角
- `episode_speed_list` - 速度

**导航指令数据：**
- `episode_x_command_far_list`, `episode_y_command_far_list` - 远距离导航点坐标（全局坐标系）
- `episode_command_far_list` - 远距离导航指令
- `episode_x_command_near_list`, `episode_y_command_near_list` - 近距离导航点坐标（全局坐标系）
- `episode_command_near_list` - 近距离导航指令
- `episode_x_target_list`, `episode_y_target_list` - 目标点坐标

**运动状态数据：**
- `episode_acceleration_list` - 加速度
- `episode_angular_velocity_list` - 角速度
- `episode_action_list` - 动作（原始格式，非 one-hot）

**相机路径数据：**
- `episode_image_front_list` - 前视相机路径列表
- `episode_image_front_left_list` - 前左相机路径列表
- `episode_image_front_right_list` - 前右相机路径列表
- `episode_image_back_list` - 后视相机路径列表
- `episode_image_back_left_list` - 后左相机路径列表
- `episode_image_back_right_list` - 后右相机路径列表

**相机标签数据：**
- `cam_id_list` - 相机标签列表（从 `camera_labels` 读取）

**元信息：**
- `scenario_id`, `town_id`, `route_id`, `weather_id` - 场景元信息

### 2. `window.py` 生成的字段

该文件读取中间 pkl，进行滑窗处理和坐标系转换，生成最终的单个样本 pkl 文件：

**历史状态数据（window_size=5）：**
- `his_theta` - 历史航向角（相对当前帧，已归一化）
- `his_speed` - 历史速度
- `his_acceleration` - 历史加速度
- `his_angular_velocity` - 历史角速度
- `his_action` - 历史动作（转换为 39 维 one-hot）

**导航指令数据（window_size=5，已转换到自车坐标系）：**
- `x_command_far`, `y_command_far` - 远距离导航点坐标
- `command_far` - 远距离导航指令
- `x_command_near`, `y_command_near` - 近距离导航点坐标
- `command_near` - 近距离导航指令

**未来轨迹数据（horizon=10，已转换到自车坐标系）：**
- `fur_x` - 未来轨迹 x 坐标
- `fur_y` - 未来轨迹 y 坐标

**相机路径数据（从历史窗口取最后两帧）：**
- `his_cam_front` - 前视相机（当前帧）
- `his_cam_front_time` - 前视相机（前一帧）
- `his_cam_front_left` - 前左相机
- `his_cam_front_right` - 前右相机
- `his_cam_back` - 后视相机
- `his_cam_back_time` - 后视相机（前一帧）
- `his_cam_back_left` - 后左相机
- `his_cam_back_right` - 后右相机

**相机标签（从历史窗口取最后一个）：**
- `cam_id` - 相机标签（动态相机样本）
- `skill_cam` - 固定视角相机路径（固定相机样本）

**元数据：**
- `status` - 样本唯一标识符

## `camera_labels` 的使用方式

### 1. 在 `generate_data.py` 中的使用（第 120-131 行）

```python
# 读取 camera_labels/<RouteName>.json
cam_id_list = []
try:
    with open((cam_id_path + '.json'), 'r') as f:
        cam_data = json.load(f)
        if(len(cam_data) != step_sum):
            raise Exception(f'cam id num in {route_name} is wrong!')
        for step in range(step_sum):
            cam_id_list.append(cam_data[f"{step}"])  # 读取每个时间步的相机标签
except FileNotFoundError:
    print(f"file {cam_id_path + '.json'} does not exist, skip it")
    return None  # 如果文件不存在，跳过该 route
```

作用：
- 读取每个时间步的相机标签（可为 `"NULL"` 或特定视角如 `"CAM_FRONT_RIGHT"`）
- 验证标签数量与帧数一致
- 文件缺失则跳过该 route

### 2. 在 `window.py` 中的使用（第 149、172、258 行）

```python
# 在 _split_data 中（第 149 行）
cam_id = cam_id_list[i]  # 获取当前时间步的相机标签
tmp['cam_id'] = cam_id    # 保存到样本字典中

# 在 _process_data 中（第 258 行）
dynamic_camera_data['cam_id'] = idx_data['cam_id'][-1]  # 取历史窗口最后一个 cam_id
```

作用：
- 将相机标签传递到最终样本
- 动态相机样本保存 `cam_id` 字段
- 固定相机样本不直接使用 `cam_id`，而是通过文件名后缀确定视角

### 3. 数据流总结

```
camera_labels/<RouteName>.json
    ↓ (generate_data.py 读取)
cam_id_list (列表，每个元素是 "NULL" 或相机标识)
    ↓ (保存到 train_data.pkl/val.pkl)
    ↓ (window.py 读取并滑窗处理)
cam_id (单个值，从历史窗口最后一个时间步获取)
    ↓ (保存到最终 pkl 文件)
最终样本中的 cam_id 字段
```

### 4. 关键点

- `camera_labels` 文件必须存在，否则该 route 会被跳过
- 标签数量必须与帧数完全一致
- `"NULL"` 表示该时间步无特定视角推荐
- 动态相机样本使用 `cam_id` 字段；固定相机样本通过文件名后缀确定视角
- 所有 6 路相机路径都会保存，`cam_id` 仅作为推荐/指定视角的元数据

总结：`camera_labels` 用于为每个时间步提供相机视角标签，该标签会传递到最终样本中，供模型或策略选择使用。
