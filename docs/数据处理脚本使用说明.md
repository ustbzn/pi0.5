# 数据处理脚本使用说明

本文总结仓库内和“数据处理”直接相关的脚本，包括：

- `script/data_preprocessing/` 下的正式预处理入口
- `src/data_processing/` 下的核心处理脚本
- `mogo-dataset-tools/` 下的 MOGO 数据生成、标签修正、评估导出脚本

文档重点放在“什么时候用、输入输出是什么、怎么调用”。

## 1. 两条主要数据链路

仓库里当前有两条数据处理链路：

1. `Bench2Drive / b2d` 预处理链路  
   入口是 `script/data_preprocessing/*.sh`，核心代码在 `src/data_processing/`

2. `MOGO` 数据生成与标签修正链路  
   入口主要在 `mogo-dataset-tools/`

---

## 2. Bench2Drive 预处理链路

### 2.1 推荐执行顺序

按顺序执行：

1. `bash script/data_preprocessing/generate_data.sh`
2. `bash script/data_preprocessing/window.sh`
3. `bash script/data_preprocessing/get_statistics.sh`

### 2.2 环境变量

执行前通常需要先设置路径：

```bash
source script/set_path.sh
```

其中至少要确认：

- `DATA_DIR`：原始数据根目录
- `CAMERA_LABEL_DIR`：相机标签目录

### 2.3 `script/data_preprocessing/generate_data.sh`

用途：
- 将原始 Bench2Drive route 数据整理成 episode 级别的 `pkl`

实际调用：

```bash
python src/data_processing/generate_data.py \
    --dataset_path "$DATASET_PATH" \
    --cam_id_path "$CAM_ID_PATH" \
    --work_dir "$WORK_DIR" \
    --target_dir datasets/b2d
```

核心脚本：
- [generate_data.py](/pcpt/pcpt/project/lijun/.code/Drive_pi/src/data_processing/generate_data.py:270)

输入：
- 原始 route 数据目录
- camera label 目录

输出：
- `datasets/b2d/train/train_data.pkl`
- `datasets/b2d/val/val.pkl`

适用场景：
- 第一次把原始 Bench2Drive 数据组织成可继续切窗的中间格式

### 2.4 `script/data_preprocessing/window.sh`

用途：
- 将 `train_data.pkl / val.pkl` 切成模型训练直接使用的单样本 `pkl`

实际调用：

```bash
python src/data_processing/window.py \
    --work_dir "$WORK_DIR" \
    --window_size 4 \
    --horizon 6 \
    --stride 5 \
    --generate_fixed False \
    --dynamic_dir "datasets/b2d"
```

核心脚本：
- [window.py](/pcpt/pcpt/project/lijun/.code/Drive_pi/src/data_processing/window.py:353)

关键参数：
- `--window_size`：历史窗口长度
- `--horizon`：未来轨迹长度
- `--stride`：下采样步长，`5` 通常表示把 10Hz 降到 2Hz
- `--generate_fixed`：是否同时生成固定相机版本
- `--dynamic_dir`：动态相机数据输出目录

输入：
- `generate_data.py` 产生的 episode 级 `pkl`

输出：
- `datasets/b2d/train/*.pkl`
- `datasets/b2d/val/*.pkl`

说明：
- 脚本会读取 `train_data.pkl / val.pkl` 后切窗并落盘单样本
- 处理中会删除原始的 episode 级 `pkl`

### 2.5 `script/data_preprocessing/get_statistics.sh`

用途：
- 统计训练数据分布，生成归一化配置

实际调用：

```bash
python src/data_processing/get_statistics.py \
    --data_path "$DATA_PATH" \
    --output_path "$OUTPUT_PATH"
```

核心脚本：
- [get_statistics.py](/pcpt/pcpt/project/lijun/.code/Drive_pi/src/data_processing/get_statistics.py:205)

输入：
- 单样本 `pkl` 目录，例如训练集目录

输出：
- `statistics.json`

适用场景：
- 训练前准备标准化参数

## 3. MOGO 数据生成链路

### 3.1 `parseRosBag-2O-Poutine_junv2_50f_merge_hdmap_p2lane.py`

用途：
- 从 MOGO rosbags、拆分图像、标签中生成带 `meta_action`、`traj_p2lane_stable`、HDMap 信息的 `pkl`

脚本入口：
- [parseRosBag-2O-Poutine_junv2_50f_merge_hdmap_p2lane.py](/pcpt/pcpt/project/lijun/.code/Drive_pi/mogo-dataset-tools/parseRosBag-2O-Poutine_junv2_50f_merge_hdmap_p2lane.py:2568)

关键参数：
- `--rosbags-root`：原始 bag 根目录
- `--images-root`：拆分图像根目录
- `--output-root`：pkl 输出根目录
- `--labels-root`：标签根目录
- `--write-json`：是否同时输出 JSON 调试结果
- `--skip-existing`：遇到已有结果跳过
- `--limit`：仅处理前 N 个切片
- `--hdmap-sql`：HDMap sqlite 路径

示例：

```bash
python mogo-dataset-tools/parseRosBag-2O-Poutine_junv2_50f_merge_hdmap_p2lane.py \
  --rosbags-root /path/to/rosbags \
  --images-root /path/to/images \
  --output-root /path/to/output_pkls \
  --labels-root /path/to/labels \
  --skip-existing
```

适用场景：
- 从原始 MOGO bag 数据重新产出训练/测试 pkl

### 3.2 `parseRosBag-2O_py3.py`

用途：
- Python 3 版旧链路解析脚本，适合旧目录结构或较轻量的 JSON 生成流程

脚本入口：
- [parseRosBag-2O_py3.py](/pcpt/pcpt/project/lijun/.code/Drive_pi/mogo-dataset-tools/parseRosBag-2O_py3.py:1019)

适用场景：
- 历史数据兼容
- 不需要 p2lane / hdmap 增强时的旧流程

### 3.3 `json_to_pkl_py3.py`

用途：
- 将 JSON 样本批量转换成 PKL

脚本入口：
- [json_to_pkl_py3.py](/pcpt/pcpt/project/lijun/.code/Drive_pi/mogo-dataset-tools/json_to_pkl_py3.py:209)

关键参数：
- `--jsons-root`：json 根目录
- `--output-dir`：pkl 输出目录
- `--dates`：只处理指定日期目录
- `--skip-existing`：已有 pkl 时跳过

示例：

```bash
python mogo-dataset-tools/json_to_pkl_py3.py \
  --jsons-root /pcpt/pcpt/data/VLA/MOGO/jsons \
  --output-dir /pcpt/pcpt/data/VLA/MOGO/mogo_dataset/train \
  --skip-existing
```

适用场景：
- 已有 JSON 数据，只需要转成训练用 PKL

## 4. MOGO `meta_action` 修正与评估链路

这部分脚本主要用于：

- 根据 `traj_p2lane_stable` 修正 `meta_action`
- 用 Qwen-VL 再次修正部分标签
- 输出混淆矩阵、失败样本、典型视频

### 4.1 `update_meta_action_by_p2lane.py`

用途：
- 使用 `traj_p2lane_stable` 规则修正 `meta_action`

脚本入口：
- [update_meta_action_by_p2lane.py](/pcpt/pcpt/project/lijun/.code/Drive_pi/mogo-dataset-tools/update_meta_action_by_p2lane.py:688)

关键参数：
- `--input-dir`：输入 pkl 根目录
- `--output-dir`：输出目录
- `--inplace`：原地覆盖
- `--backup`：原地覆盖前备份
- `--dry-run`：只统计不写回
- `--context-k`：时间上下文窗口
- `--min-valid-points`：最少有效 `traj_p2lane_stable` 点数
- `--center-threshold`
- `--out-threshold`
- `--write-report`：输出报告前缀

示例：

```bash
python mogo-dataset-tools/update_meta_action_by_p2lane.py \
  --input-dir /path/to/pkls \
  --output-dir /path/to/pkls_after_p2lane \
  --write-report /path/to/p2lane_report
```

### 4.2 `ali_api.py`

用途：
- 使用 Qwen-VL 对特定 `meta_action` 样本进一步修正

脚本入口：

## 7. 推荐使用方式

### 7.1 如果你处理 Bench2Drive 训练数据

执行顺序：

```bash
source script/set_path.sh
bash script/data_preprocessing/generate_data.sh
bash script/data_preprocessing/window.sh
bash script/data_preprocessing/get_statistics.sh
```

### 7.2 如果你处理 MOGO 原始 bag 数据

推荐顺序：

1. 用 `parseRosBag-2O-Poutine_junv2_50f_merge_hdmap_p2lane.py` 生成 `pkl`
2. 用 `update_meta_action_by_p2lane.py` 做规则修正
3. 需要视觉复核时，用 `ali_api.py`
4. 需要整体验证时，用 `run_meta_action_test_pipeline.py`
5. 需要导出错例视频时，用：
   - `export_meta_action_failure_videos.py`
   - `export_meta_action_label_typical_videos.py`

## 8. 注意事项

1. `mogo-dataset-tools/` 下有较多历史版本和备份脚本，例如：
   - `*_bak.py`
   - `*_test.py`
   - `*OK.py`

   默认优先使用本文列出的主脚本，不要随意混用历史版本。

2. `run_meta_action_test_pipeline.py --report-only` 不会重新跑模型或标签修正，但仍可能重建 mismatch 导出，因此耗时不一定短。

3. `ali_api.py` / `run_meta_action_test_pipeline.py` 涉及 DashScope API，执行前要确认：
   - `DASHSCOPE_API_KEY` 已设置
   - 输出目录可写

4. 一些脚本里默认路径写死在代码中，运行前应先检查默认值是否和当前机器一致。

5. 仓库内同时存在 `Python2/Python3`、旧版/新版 MOGO 解析脚本。除非明确要复现旧数据，否则优先使用带 `py3` 或 `p2lane/hdmap` 的新版脚本。
